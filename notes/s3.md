# S3

## CDK vs Terraform

| | Terraform (`labs/01-s3/iac/terraform`) | CDK (`labs/01-s3/iac/cdk`) |
|---|---|---|
| Engine | Terraform calls the S3 API directly | CDK synthesizes CloudFormation; CloudFormation calls the API |
| State | Local `terraform.tfstate` | Held by the CloudFormation stack in the account |
| Bucket name | Built in HCL (`prefix-region-random`) | Left to CloudFormation (`s3labstack-bucket...`), read from the `BucketName` output |
| Public access block | Separate `aws_s3_bucket_public_access_block` resource | `blockPublicAccess: BLOCK_ALL` on the `Bucket` construct |
| Delete a non-empty bucket | `force_destroy = true` (provider empties it) | `autoDeleteObjects: true` (adds a custom-resource Lambda that empties it) + `removalPolicy: DESTROY` |
| Default retention | Destroy deletes the bucket | Buckets are **retained** on stack delete unless `removalPolicy: DESTROY` |
| Tags | `default_tags` on the provider | `Tags.of(app).add(...)` (an Aspect applied at synth) |
| Account guard | `allowed_account_ids` | None built in; rely on `whoami.sh` and the credential chain |
| One-time setup | `terraform init` | `cdk bootstrap` (creates the `CDKToolkit` stack per account/region) |
| Tests | `terraform plan` / tflint | `Template.fromStack` assertions in jest, no AWS needed |

Gotcha: `autoDeleteObjects` means the stack has more than the bucket — a Lambda, its IAM role
and a bucket policy. Expect them in `cdk diff` and the console.
